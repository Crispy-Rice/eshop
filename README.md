## 三条主线的设计结论

**1. 一致性：以数据库为最终账本，Redis 只是"闸门"**

Redis 承担高并发下的写入压力，MySQL 承担正确性。所有 Redis 的库存/券库存都是**前置拦截器**，DB 侧用条件更新（`WHERE stock >= n`）或唯一索引兜底，两者定时对账修正。**绝不出现"只有 Redis 有库存"的情况**——Redis 挂了，下单降级为拒绝，而不是本地兜底（本地兜底会造出新的超发）。

**2. 并发安全：排队 + 原子操作 + 幂等**

- 热点 SKU：库存分片 + FIFO 令牌排队，把随机抢购转成有序消费。
- 领券：单条 Lua 脚本完成"查库存 → 查限领 → 扣减 → 记领取"，Redis 单线程保证原子。
- 接口：幂等键 + 状态机前置守卫 + 唯一索引三层去重。

**3. 资金准确：一切金额用整型分，后端是唯一裁决者**

前端算价只做展示，提交时后端重算并逐项对比，不一致返回 `409 PRICE_CHANGED` 让用户确认。优惠分摊用**最大余数法**保证分摊之和恰好等于总优惠，退款时按分摊明细原路扣回。所有金额字段是 `BIGINT` 存分，代码里禁止 `float`/`double`。

## 关键设计取舍

| 取舍点 | 选择 | 理由 |
|---|---|---|
| 库存扣减时机 | 下单预占（Redis）+ 支付成功后 DB 实扣 | 防超卖同时不长期锁库存 |
| 订单超时 | 延迟消息 + 定时扫描双保险 | 延迟消息可能丢，扫描兜底 |
| 优惠券叠加 | 类型互斥 + 同类型只取最优 1 张 | 枚举组合可控，避免规则爆炸 |
| 拆单 | 下单时按店铺拆母子单 | 支付用母单，履约/退款用子单 |
| 退货库存恢复 | 入库质检后由 WMS 事件触发 | 防止"申请即回补"造成二次超卖 |
| 优惠券退款 | 整单退→券退回，部分退→不退 | 兼顾体验与防刷 |
| 运费冲突 | 冲突时以首重最高的 SKU 为准 | 需求指定；同仓合并计费不收多次首重 |

## 技术选型

- **语言/框架**：Java 21 + Spring Boot 3（备选 Go）
- **存储**：MySQL 8.0（分库分表预留）、Redis 7（Cluster）、Elasticsearch（商品搜索）
- **消息**：RocketMQ（事务消息 + 延迟消息）或 Kafka
- **分布式事务**：本地消息表 + 定时对账；跨服务走最终一致，不用强 2PC
- **ID 生成**：雪花算法（订单号含分片与时间位），字符串形式返回前端
- **可观测**：SkyWalking 链路追踪、Prometheus + Grafana 指标、集中式日志

---

> 所有文档中的金额单位统一为**分（整数）**，时间统一为 `DATETIME(3)`，ID 统一为 `BIGINT`（前端按字符串处理）。
