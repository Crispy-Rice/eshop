## 仓库是干什么的

买家下单时，系统按**收货地址所在的地区**决定从哪个仓发货：

1. 先看**区域规则** —— 你给某个仓配了「覆盖区域」，收货地命中就从这个仓发。
   命中多个时，**地区越具体越优先**（配了「深圳」的仓比配了「广东」的仓优先）。
2. 都没命中 → 走**默认仓**。所以默认仓必须有，而且**不允许停用**。

## 那个仓没货会怎样

**会自动从别的仓发。** 顺序是：

```
命中的规则仓 → 默认仓 → 其余启用的仓（按建立顺序）
```

系统取**第一个能一次发齐这单全部商品**的仓。所以"上海仓没货、其他仓有货"时，
上海的买家**照样能买到**，只是从另一个仓发出（订单上会显示实际发货仓）。

两种情况会失败：

- **所有仓都不够**：结算页会说明"库存不足"。
- **商品分散在不同仓**，没有哪个仓能一次发齐：结算页会提示"把商品分开下单"。
  这确实可行 —— 单独下其中一件时，它会去有货的那个仓。

系统**不会**把一单的货从多个仓凑起来发。

## 库存行从哪来

刚建仓时，系统会给**你店里全部规格**在这个仓预建一条 0 库存的行，
你去库存页填数量就行。发布新商品后，打开库存页也会自动补上缺的行。

没铺过货的规格，在下单系统眼里就等于「这个仓没货」—— 会自然被跳过。

## 买家看到的库存

- 库存充足：显示「有货」。
- 库存较少：显示「仅剩 N 件」（展示值做了模糊，不是精确数量）。
- 可售为 0：商品页显示**「已售罄」**，加购按钮不可点。

「可售」会随下单预占、支付、发货变化，不完全等于你填的数字。

## 库存为什么不能直接改小

如果这个规格有**在途的预占或待发货**，把总量改成比它小的数会让账面出现负数，
系统会拒绝。等那批订单发完或取消再改。

## 订单从哪个仓发，发货后能改吗

不能。**发货仓在下单那一刻就定下来了**，之后发货、退货入库都认这个记录。
你事后调整区域规则，不会影响已经在途的订单。
